# GLM Publisher v0.6 — Publication complète

La v0.6 conserve le même principe que la v0.5 : **Google Docs est le document de travail ; seul un instantané validé est public.**

## 1. L'onglet « Fiche de publication »

Dans le Google Doc, cliquer sur **+** dans la liste « Onglets du document » et créer un onglet nommé exactement :

`Fiche de publication`

Dans cet onglet, coller les lignes utiles ci-dessous (une propriété par paragraphe, séparée par **:**). Ne pas inventer de données : laisser un champ absent tant qu'il n'est pas confirmé.

```text
Présentation : Bref résumé de la traduction (facultatif).
Auteur : Nom de l'auteur original
Traduction : Noms des traducteurs
Correction : Noms des correcteurs et relecteurs
Mise en page : Équipe ou personne créditée
Source : Titre de l’œuvre originale
Niveau : 1c
Version : V1dFr
PDF VF : https://exemple.org/document-fr.pdf
PDF VO : https://exemple.org/document-vo.pdf
Source URL : https://exemple.org/texte-original
Image aperçu : https://exemple.org/apercu.jpg
Discord : https://exemple.org/communaute
Avertissement : Règles amateurs non officielles.
```

Les adresses `exemple.org` sont **des exemples non fonctionnels**, à remplacer par de vrais liens publics.

### Image d'aperçu

Le champ `Image aperçu` doit contenir une **URL HTTPS directe vers une image**, publiquement consultable sans connexion (PNG, JPEG ou WebP). Le code ne sait pas encore extraire automatiquement la première page d'un PDF, et n'expose pas les images provenant de documents Drive privés.

Une image hébergée sur un dépôt GitHub public ou sur un hébergement d'images public convient, sous réserve des droits de publication. Ne pas mettre une image privée sur un dépôt public pour contourner l'autorisation Google.

Le bloc d'aperçu devient cliquable vers le PDF VF, puis le PDF VO s'il n'y a pas de VF.

### Lecture des onglets

- **VF** : source du texte des règles et des sections.
- **Fiche de publication** : crédits, informations d'édition, liens et image (facultatif).
- **Change-log** : historique éditorial, lu séparément.

La fiche et le Change-log ne peuvent pas être sélectionnés comme onglet principal de traduction. Les commentaires et suggestions non acceptées restent dans Google Docs et ne sont pas inclus dans le site public.

## 2. Publication contrôlée

Depuis **GLM Publisher — Administration** :

1. Choisir le document enregistré puis cliquer **Analyser les modifications**.
2. Vérifier les modifications des sections.
3. Vérifier les champs de la **fiche de publication** et les liens (leur caractère public reste à contrôler manuellement).
4. Pour la fiche et le Change-log, choisir indépendamment :
   - **Conserver** : garder la dernière version publiée.
   - **Mettre à jour** : remplacer par la version acceptée du Google Doc.
   - **Masquer** : retirer cet élément de la prochaine version publique.
5. Confirmer la publication. Il est possible de ne modifier que la fiche ou le Change-log, sans republier le texte.

Chaque version publique est conservée dans les instantanés Google Sheets. La restauration replace aussi la fiche et le Change-log tels qu'ils existaient dans la version choisie.

## 3. Recherche dans les publications

Le moteur de recherche de la v0.6 n'est **pas la recherche native Google Sites**. C'est une page publique de GLM Publisher qui utilise l'onglet `SearchIndex` du registre Google Sheets, construit **seulement à partir des versions validées**.

L'URL de recherche a cette forme :

```text
https://script.google.com/macros/s/IDENTIFIANT_DÉPLOIEMENT_PUBLIC/exec?search=1
```

Il est possible de l'intégrer dans Google Sites via **Pages → + → Intégration sur page entière**, puis de nommer cette page « Recherche GLM ».

Après publication d'une version avec la v0.6, l'index est mis à jour automatiquement. Pour indexer une page publiée sous v0.5 sans republier, choisir ce document dans le panneau et cliquer **Indexer la version déjà publiée**.

Le moteur actuel réalise une recherche simple sans distinction de majuscules ni d'accents et renvoie jusqu'à 50 résultats, regroupés par section. Il n'indexe ni les commentaires ni les suggestions refusées. En cliquant sur un résultat, l'utilisateur ouvre la page GLM correspondante si une URL Google Sites a été associée au document, ou l'application publique.

**Limitation :** une recherche depuis l'index n'ouvre pas encore automatiquement le sous-panneau repliable pertinent dans Google Sites. Cette amélioration pourra suivre une validation du premier test.

## Raccourcis de travail dans l'administration

Pour chaque Google Doc enregistré, le panneau affiche **Modifier dans Google Docs** ainsi que **Ouvrir le dossier Drive** lorsqu'un dossier parent est accessible. Le premier ouvre directement l'onglet éditorial ; le second ouvre le dossier contenant le fichier, permettant de retrouver les PDF, aperçus, fichiers sources et autres éléments du projet. Les onglets « VF », « Change-log » et « Fiche de publication » disposent également de liens directs vers leurs éditeurs.

Le dossier est identifié à partir des métadonnées Google Drive de ce document lors de sa sélection ; l'URL n'est jamais recopiée dans les versions publiées. La recherche du dossier n'est exécutée qu'après vérification des droits de l'administrateur. Un dossier inaccessible ne bloque ni l'analyse ni la publication.

## 4. Déploiement du code

Les sources de la v0.6 sont :

- `Code.gs`
- `Admin.html`
- `Publication.gs`
- `Search.gs`
- `appsscript.json`

Le workflow GitHub Actions et clasp synchronise ces **cinq fichiers** vers le **brouillon Apps Script** lorsque l'automatisation est activée.

Après contrôle dans Apps Script, il reste à mettre à jour manuellement les **deux déploiements Web existants** (public et administration) avec **Nouvelle version**.

Aucun appel à `installerGLM` n'est nécessaire : le nouveau `SearchIndex` est créé à la première publication/indexation.

## 5. Précautions

- La v0.6 ne modifie pas les Google Docs sources. Les commentaires et suggestions restent intactes.
- La fiche de publication peut contenir des crédits de personnes : ne publier que ceux dont la diffusion publique est voulue.
- Les URL PDF et image doivent être accessibles sans connexion Google, et ne doivent pas pointer vers un document privé.
- La recherche ne fournit pas d'indexation SEO garantie de Google Sites ou de Google Search.
- Prévoir une revue visuelle des polices, tableaux, illustrations et sections longues avant migration d'autres bandes.
